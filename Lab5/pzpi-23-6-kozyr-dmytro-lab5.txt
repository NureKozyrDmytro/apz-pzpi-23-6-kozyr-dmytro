5.2 Короткий опис проєкту
CargoGuard - це програмна система для контролю перевезення цінних вантажів, наприклад картин, музейних експонатів, архівних матеріалів або інших об’єктів, для яких важливо зберігати стабільні умови транспортування.
Основна ідея системи полягає в тому, щоб контролювати стан контейнера під час перевезення. Система отримує телеметричні дані від IoT-компонента, зберігає їх на сервері, порівнює температуру та вологість із допустимими межами для конкретного вантажу і створює інциденти у випадку порушення умов перевезення.
Система складається з кількох основних частин:
* backend API;
* база даних PostgreSQL;
* web-застосунок;
* мобільний застосунок;
* IoT-емулятор;
* конфігурація масштабування backend.
Backend відповідає за основну бізнес-логіку системи: автентифікацію користувачів, розмежування доступу за ролями, роботу з вантажами, контейнерами, перевезеннями, телеметрією, інцидентами та журналом подій. Також backend приймає дані від IoT-емулятора і створює інциденти, якщо показники виходять за встановлені межі.
Web-застосунок використовується для повноцінної роботи з системою через браузер. У ньому можна переглядати Dashboard, керувати вантажами, контейнерами та перевезеннями, переглядати телеметрію, інциденти, журнал подій, а також виконувати адміністративні дії. Інтерфейс підтримує українську та англійську локалізацію.
Мобільний застосунок призначений для швидкого перегляду стану перевезень зі смартфона. Він дозволяє авторизуватися, переглядати список перевезень, відкривати деталі перевезення, переглядати телеметрію та інциденти, а також вирішувати інциденти за наявності відповідної ролі.
IoT-компонент реалізовано у вигляді емулятора, який імітує роботу контейнера з датчиками температури, вологості та відкриття дверей. Це дозволяє перевіряти роботу системи без використання реального фізичного пристрою.
Для демонстрації масштабування backend було підготовлено конфігурації з одним та трьома backend-інстансами через Nginx Load Balancer. Це дозволило показати, що серверна частина може працювати не лише як один процес, а й як кілька однакових backend-контейнерів за балансувальником навантаження.
5.3 Заплановані та виконані функції
На початку роботи над проєктом було заплановано створити систему, яка дозволяє контролювати перевезення цінних вантажів і реагувати на порушення умов транспортування. Основний сценарій роботи мав включати створення вантажу, контейнера, перевезення, отримання телеметрії, перевірку показників і створення інцидентів.
У результаті було реалізовано backend-частину системи. Вона містить REST API для роботи з користувачами, вантажами, контейнерами, перевезеннями, телеметричними записами, інцидентами та журналом подій. Також реалізовано авторизацію через JWT і рольову модель доступу.


Було реалізовано три основні ролі користувачів:
* admin;
* operator;
* observer.
Користувач з роллю observer може переглядати дані системи. Operator може працювати з основними сутностями системи, змінювати статуси перевезень і вирішувати інциденти. Admin має додатковий доступ до керування користувачами, експорту, імпорту та резервного копіювання даних.
Для предметної області CargoGuard було реалізовано роботу з вантажами. Для кожного вантажу можна вказати назву, тип, опис, мінімальну та максимальну температуру, а також мінімальну та максимальну вологість. Ці значення використовуються системою для перевірки телеметрії під час перевезення.
Також було реалізовано роботу з контейнерами. Контейнер має серійний номер, назву, статус і API key, який використовується IoT-компонентом для надсилання телеметрії. У web-застосунку API key відображається у скороченому вигляді, щоб не показувати його повністю у таблиці.
Для перевезень було реалізовано створення, редагування, перегляд деталей і зміну статусів. Перевезення може бути запланованим, активним, завершеним або скасованим. Для активного перевезення система може приймати телеметрію, порівнювати її з межами вантажу та створювати інциденти.
Було реалізовано обробку телеметрії. Система приймає температуру, вологість і події відкриття контейнера. Якщо температура або вологість виходять за допустимі межі вантажу, backend створює інцидент. Інциденти можна переглядати у web- та мобільному застосунках, а користувачі з відповідними правами можуть їх вирішувати.
Для демонстрації роботи системи у web-застосунку було додано можливість запитати телеметрію для активного перевезення. Це спрощує демонстрацію, оскільки користувач може згенерувати нові показники контейнера прямо зі сторінки деталей перевезення без використання Postman. Після запиту телеметрії система оновлює показники та створює інцидент, якщо значення порушують межі вантажу.
Web-застосунок було реалізовано з підтримкою двох мов: української та англійської. У ньому доступні сторінки Dashboard, Shipments, Shipment Details, Cargo, Containers, Incidents, Event Logs та Admin. Для форм створення і редагування додано підписи полів, локалізовані повідомлення, фільтри, кнопки дій і обробку помилок.
Мобільний застосунок було реалізовано для Android. Він дозволяє користувачу увійти в систему, переглядати перевезення, користуватися пошуком і фільтрами, відкривати деталі перевезення, переглядати телеметрію та інциденти. Після входу JWT-токен зберігається локально і автоматично додається до захищених API-запитів.
Для масштабування backend було реалізовано окремі Docker Compose-конфігурації. Одна конфігурація запускає один backend-інстанс через Nginx, інша - три backend-інстанси через Nginx. Для перевірки роботи масштабування було додано endpoint /health, який повертає назву backend-інстанса. Це дозволило показати, що Nginx розподіляє запити між backend-1, backend-2 та backend-3.
Також було проведено навантажувальне тестування за допомогою Locust. Тестування виконувалося для одного та трьох backend-інстансів з однаковими параметрами. За результатами тестування система обробила навантаження без помилок, а масштабована конфігурація показала кращі значення середнього та максимального часу відповіді.
Не всі можливості, які були описані як потенційний розвиток системи, були реалізовані в поточній версії. Зокрема, у системі поки що не реалізовано реальне GPS-відстеження контейнера, контроль ударів і вібрацій, датчик освітлення, моніторинг заряду фізичного пристрою та інтеграцію штучного інтелекту. Ці функції залишено для подальших версій, оскільки вони потребують додаткових датчиків, більшого обсягу даних і окремого проєктування.
